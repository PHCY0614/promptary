# Promptary

私人、視覺化的 AI 生圖 prompt 收藏與實驗筆記工具。

把參考圖片、原始 prompt 與自己的生成嘗試放在一起，保存不同版本的提示詞、成果與心得，方便之後找回、複製及比較。

> 目前為本機試用版：資料保存在使用者的瀏覽器，尚未提供登入或跨裝置同步。

## 使用流程

1. 上傳參考圖片，貼上 prompt、來源與收藏筆記；也可以先存圖片，之後補文字。
2. 在首頁透過搜尋、標籤與狀態篩選找回收藏。
3. 複製 prompt 到生圖平台使用。
4. 在收藏內新增「我的嘗試」，保存實際 prompt、成果圖片、平台、評分與心得。
5. 選取兩張圖片並排比較，或匯出備份留存。

## 目前功能

- **收藏 Gallery**：圖片卡片、最愛、狀態篩選，以及最新收藏／最近更新／最早收藏排序。
- **文字搜尋**：搜尋原始 prompt、標籤、收藏筆記、來源，以及嘗試的 prompt、心得與平台。
- **多選標籤**：採 OR 邏輯，符合任一已選標籤即可顯示；可在「所有標籤」搜尋並多選。「重設」清空搜尋、狀態與標籤篩選，保留排序。
- **收藏管理**：新增、編輯、刪除，並可選擇參考圖或成果圖作為封面。
- **嘗試紀錄**：一筆收藏可有多次嘗試，每次可保存多張圖片及獨立 prompt；修改嘗試不影響原始 prompt。
- **平台選單**：PixAI、Gemini、ChatGPT、自訂。自訂名稱可加入選單或刪除；刪除選項不改寫既有紀錄。
- **Prompt 分類閱讀**：以本機中英文詞彙規則分類，支援手動調整與保存。未使用 AI；不確定或跨類內容放入「未分類」，原文與複製順序不變。
- **圖片比較**：可選參考圖或成果圖，最多選兩張；再次點擊可取消。桌面左右對照圖片與 prompt，窄螢幕改為上下排列。
- **本機備份**：從「管理」選單匯出或匯入 JSON，還原收藏、上傳圖片、嘗試與 prompt 分類。

全新瀏覽器首次開啟時，只有一張「加入第一個咒語！」的起始卡片。有既有本機資料時不會被示範內容覆蓋。

## 本機資料與備份

收藏與圖片保存在 **IndexedDB**；上傳圖片以 Blob 保存原始位元組。自訂平台選單另外保存在 **localStorage**。

- 資料依瀏覽器、使用者設定檔及網站來源分開保存。不同裝置、瀏覽器，或不同網址／連接埠，不會自動共用資料。
- 清除網站資料或結束無痕瀏覽可能失去收藏，請定期匯出備份。
- 沒有登入保護；能使用同一瀏覽器設定檔的人也可能存取本機收藏。
- 目前參考圖片上傳支援 JPG、PNG、WebP，單張上限 2 MB；嘗試成果圖片的上傳限制尚未完全統一。
- 圖片以畫面縮小方式呈現，目前尚未建立獨立縮圖檔案。大量圖片仍可能占用較多記憶體。

### 匯出與匯入

1. 點「管理 → 匯出」下載 JSON。
2. 在另一個瀏覽器或裝置開啟 Promptary，點「管理 → 匯入」。
3. 選擇備份，查看預計新增與跳過的數量，再確認匯入。

單份匯入檔案上限為 **100 MB**。以收藏 ID 判斷重複；同 ID 的收藏會跳過，**不會合併或覆蓋既有版本**。因此這是手動備份搬移，並非雙向同步。

格式驗證通過後才允許匯入，寫入使用 IndexedDB 原子交易。儲存失敗時保留原收藏及匯入預覽，可在排除問題後重試。

備份包含上傳圖片與文字，但目前不包含自訂平台選單偏好。舊資料若含外部圖片網址，匯出只保存網址，不會下載遠端圖片；介面不提供圖片網址輸入。分享備份前請確認圖片、來源及筆記適合提供給對方。

## 本機開發

技術組合：React 19、TypeScript、Vite 8、Tailwind CSS v4，以及瀏覽器 IndexedDB。介面以 Figma Make 產出為基礎持續調整，透過 AI 輔助開發。

專案工具設定使用 Node.js 22 與 pnpm 10.34.3，請使用近期的 Node.js 22 修補版本。

```sh
pnpm install
pnpm dev
```

依終端機顯示的網址開啟。設定預設連接埠為 `8443`；也可以指定本機預覽位址：

```sh
pnpm dev --host 127.0.0.1 --port 5173
```

若已有開發伺服器執行，直接使用原網址即可，不必重複啟動。

### 檢查與建置

```sh
pnpm typecheck
pnpm test
pnpm build
```

建置輸出位於 `dist/`。可用以下指令預覽建置結果：

```sh
pnpm preview --host 127.0.0.1 --port 4173
```

測試涵蓋本機資料遷移、圖片位元組往返、儲存失敗與重試、多分頁版本衝突、備份格式與重複匯入、prompt 分類及圖片比較選取邏輯。這些測試不取代手機與桌面的實際操作檢查。

## 關鍵程式與資料流

```text
新增／編輯表單
  → store.ts：序列化資料更新
  → archiveStorage.ts：圖片轉 Blob、版本檢查、IndexedDB 交易
  → 寫入成功後更新 React 畫面

匯入 JSON
  → backup.ts：格式檢查、依 ID 去重
  → ImportBackup.tsx：顯示預覽並等待確認
  → store.ts → archiveStorage.ts → 更新卡片
```

| 檔案 | 用途 |
| --- | --- |
| `src/App.tsx` | 頁面切換、表單與儲存錯誤提示 |
| `src/Gallery.tsx` | 首頁搜尋、排序、篩選與卡片 |
| `src/DetailView.tsx` | 收藏詳情與嘗試紀錄 |
| `src/CollectionModal.tsx`、`src/AttemptModal.tsx` | 新增與編輯表單 |
| `src/PromptReader.tsx`、`src/promptClassification.ts` | Prompt 閱讀、分類規則與手動調整 |
| `src/ImageComparison.tsx`、`src/comparisonImages.ts` | 圖片與 prompt 對照、選取邏輯 |
| `src/store.ts`、`src/archiveStorage.ts` | 狀態更新與本機持久化 |
| `src/ImportBackup.tsx`、`src/backup.ts` | 管理選單、備份匯入與檢查 |
| `src/types.ts`、`src/seed.ts` | 資料型別與首次使用的起始收藏 |
| `tests/` | 行為與資料可靠性測試 |
| `docs/開發說明.md` | 分階段開發紀錄，較早段落可能描述舊版行為 |

## 發布與後續範圍

目前可建置為靜態網站；發布網站不會把開發者瀏覽器裡的私人收藏一起上傳。全新使用者會取得起始卡片，自己的資料仍保存在自己的瀏覽器。

### GitHub Pages 部署

已提供 `.github/workflows/pages.yml` 自動部署流程：

1. 將專案原始碼上傳到 GitHub 儲存庫的 `main` 分支（包含 `.figma/make/site.json`，不要上傳 `node_modules`、`dist` 或個人備份）。
2. 在儲存庫 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
3. 推送更新，或在 **Actions → Deploy Promptary to GitHub Pages → Run workflow** 手動執行。
4. 檢查工作流程成功後，在 Pages 設定查看網站網址。

工作流程先執行型別檢查與測試，再建置並發布。Vite 會使用 Pages 提供的路徑，支援專案子路徑，無須寫死儲存庫名稱。若預設分支不是 `main`，需同步調整工作流程的分支設定。

正式網站與本機預覽是不同來源，本機收藏不會自動出現在正式網站；需要自行匯出再匯入。

先讓朋友試用本機版本，再決定是否加入登入、雲端儲存與跨裝置同步。目前不包含內建生圖 API、Threads 自動擷取、公開社群或 AI prompt 分析服務。
