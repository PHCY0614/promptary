# AI 生圖 Prompt 收藏與實驗筆記

> 目前使用 IndexedDB 本機儲存。Prompt 差異比較已移除，改為原文／分類閱讀；最新功能見「第五次改善」。前面的記錄保留開發歷程。

## 開發原則

依使用者提供的規劃逐條完成可操作流程，沿用 Figma 的 React + Vite + Tailwind 設計。新增程式以中文區塊標題標示資料、操作及畫面責任；註解解釋原因與限制。尚未確認的功能不擴充。

## 本次：快速收藏的圖片讀取與儲存失敗處理

目前是本機原型，沒有後端、登入、RLS 或跨裝置同步。首次開啟載入 seed 假資料；後續讀取此瀏覽器 localStorage 的 `prompt-archive-v2`。

資料流：選擇圖片 → `imageUpload.ts` 檢查格式、2 MB 限制及解碼 → `CollectionModal.tsx` 暫存原圖 Data URL、進度與表單文字 → `App.tsx` 呼叫 `store.addCollection` → `store.ts` 寫入 localStorage → 成功後更新 React 狀態並開啟詳情。

圖片以固定 ID 對應非同步結果，讀取途中移除或追加不會覆蓋別張圖。失敗項目保留 File 供重試；存在失敗或讀取中項目時禁止提交，避免靜默漏存圖片。原始檔案沒有壓縮，2 MB 是這一階段的暫定單張限制；整個瀏覽器容量仍可能先耗盡。

儲存失敗時不更新收藏、不關閉表單，顯示錯誤；移除較大的圖片或恢復儲存權限後，可按原儲存按鈕重試。這也套用到收藏編輯及嘗試新增、編輯的儲存結果。表單仍是記憶體狀態，主動關閉或重新整理不會保留未儲存草稿。

## 值得理解的程式

- `src/CollectionModal.tsx`：表單狀態、圖片固定 ID、非同步回寫與失敗重試。
- `src/imageUpload.ts`：FileReader 進度、錯誤處理及圖片解碼驗證；目前不是雲端上傳。
- `src/store.ts`：先持久化、再更新畫面；回傳成功與否給呼叫端。
- `src/App.tsx`：接收操作結果，成功才關閉表單，統一顯示儲存失敗。
- `tests/collection-flow.mjs`：以可控制的瀏覽器替身重現檔案及儲存失敗。

## 驗證方式

自動檢查：`node node_modules/typescript/bin/tsc --noEmit`、`pnpm build`、`node tests/collection-flow.mjs`。

手動驗收（尚未執行瀏覽器端驗收）：

1. 新增一張小於 2 MB 的 PNG，不填 prompt，保存後應進入詳情；重新整理仍可找到。
2. 填寫筆記後選擇超過 2 MB 的圖片，應顯示原因且禁止保存；移除該圖後文字仍在。
3. 選擇損壞的 PNG，應顯示解碼失敗；按重試仍會顯示錯誤，可移除並換圖。
4. 快速分批選圖、讀取途中移除其中一張，完成後應保持剩餘圖片及順序正確。
5. 在測試瀏覽器模擬 localStorage.setItem 拋出 QuotaExceededError，再保存；應保留表單且不出現新收藏。恢復寫入後重試應成功。

## 第二次改善：圖片比較與 Prompt 差異

- `computePromptDiff.ts` 以共同子序列比較英文單字、中文字及標點，保留空白和換行。超長差異改用整段標記以限制運算量。
- `PromptDiff.tsx` 顯示綠底新增／改寫、紅底刪除線；出現在選定成果下方及展開的嘗試紀錄中。
- 嘗試卡片的「複製 Prompt」直接讀取 attempt.prompt，不複製差異畫面；成功才顯示已複製，失敗提供可選取的原文。
- 此次全為畫面衍生資料，不新增後端寫入，也不改動原始 prompt 或已保存的嘗試版本。

驗證：`node tests/prompt-diff.mjs` 檢查中英文替換、空白、刪除、新增、重複字、空字串及長文，確認差異可完整還原兩份原文。瀏覽器已確認現有直式圖片完整並排及複製成功提示；手機上下排版仍待實機驗收。

## 第三次改善：原版／新版分開與位置移動

Prompt 比較現在各自保留原始與嘗試的完整文字，寬畫面左右呈現，窄畫面上下呈現。新增為綠底，刪除為紅底刪除線，相同詞的位置移動為藍底虛線。複製按鈕仍讀取 attempt.prompt。

`comparePromptVersions` 先沿用共同子序列，再把未匹配的刪除／新增詞一對一配對為移動，保留重複次數。這是文字層級的配對，無法唯一推斷使用者移動哪個重複詞，也不判斷同義詞；超長文會沿用粗略比對。標點、空白仍可能顯示增刪。

已測試 masterpiece 從開頭移到結尾、額外重複詞、新增導致位置偏移、red → blue 替換及兩版完整還原，並通過 TypeScript 與正式建置。資料只在畫面推導，沒有修改已儲存資料。本次尚未重新執行瀏覽器視覺驗收。

## 第四次改善：IndexedDB 本機儲存與錯誤提示

這次完成「舊收藏搬移 → 本機收藏新增／修改／刪除 → 重新載入」的儲存流程。仍然只在同一瀏覽器、同一網站地址保存，沒有登入、雲端或跨裝置同步。

### 資料流與關鍵程式

1. `archiveStorage.ts` 開啟 IndexedDB。若尚無資料，讀取 localStorage 舊收藏，以交易寫入新資料庫並讀回；成功後才清除舊副本。失敗或舊 JSON 損壞時保留舊資料，顯示重試畫面，不用範例覆蓋。既有空圖庫也維持空圖庫。
2. 圖片保存為 Blob，還原原始位元組、不壓縮；遠端圖片繼續保留網址。畫面載入時轉回 Data URL，以維持現有圖片顯示及 JSON 匯出介面。
3. `store.ts` 將操作排隊，每次依最新資料更新，等待完整交易成功才更新 React。資料庫版本檢查阻擋其他分頁的舊資料覆蓋新版。
4. `App.tsx` 等待成功才關閉表單。表單保存中禁止重複提交及編輯、關閉；失败後解除等待，輸入仍在。错误提示有「×」關閉按鈕，成功操作也會清除；關閉提示本身不代表儲存成功。
5. `CopyPromptButton.tsx` 統一原始、嘗試卡片及版本比較欄的複製外觀。按鈕位在標題右側，成功顯示 1.8 秒後恢復「複製」，失敗提供手動複製原文。

### 驗證

- `pnpm test`：原圖位元組不變、遷移後讀回、超過 8 MB 圖片、刪除釋放圖庫中的圖片記錄、儲存失敗回滾、遷移失敗保留舊資料、損壞 JSON、重試、並行初始化、舊分頁版本衝突、快速連續新增與關閉錯誤狀態。
- `pnpm typecheck`、`pnpm build`：型別及正式建置。
- 瀏覽器確認既有七筆收藏正常呈現，嘗試卡片複製按鈕位於 Prompt 標題旁且點擊顯示「✓ 已複製」。
- 人工回歸：加入圖片收藏後重新整理應仍在；模擬容量不足時應保留表單，點錯誤提示「×」應關閉，恢復儲存後重試成功。

### 本階段界線

IndexedDB 仍有瀏覽器及磁碟容量限制，清除網站資料會清除圖庫。此版本每次交易寫入整份收藏快照；適合先解決 localStorage 容量問題，日後大量收藏應拆成獨立資料列及縮圖。現有完整備份匯入／遠端圖片打包仍待實作。單張参考圖仍暫限 2 MB。Prompt 自動分類依約留到下一階段，先提供可調整的閱讀分類，不改原文。

## 第五次改善：移除 Prompt 差異比較，加入分類閱讀

移除紅綠／移動標記、原版新版差異並排、舊差異演算法及測試。圖片比較與完整直式圖顯示維持運作。原始 Prompt 與每次嘗試都使用相同的原文閱讀及複製介面。

### 使用流程

開啟收藏 → 在原始或嘗試 Prompt 點「分類閱讀」 → 查看人物外表、服裝與配件、姿勢與表情、背景與場景、構圖與鏡頭、光線與色彩、畫風與品質、未分類 → 如需更正，點「調整分類」，使用每段下拉選單 → 點「儲存分類」。空分類不占版面。可恢復自動分類後再保存。

### 程式與資料流

- `promptClassification.ts`：本機中英文關鍵字分類。依逗號、換行、分號等切成閱讀片段；保留括號權重及 LoRA 標記完整。不確定或命中多類時放入未分類。這不是 AI 語意理解，長句、陌生詞及跨類詞句需要手動判斷。
- `PromptReader.tsx`：原文／分類切換、緊湊詞句分組、手動分類草稿與保存狀態。原文及複製內容不因分類而重排；「完成調整」只關閉選單，仍需按「儲存分類」才持久化。
- `types.ts`：收藏與嘗試各有選填的 `promptClassification`，包含當時完整 `sourcePrompt` 與手動覆寫的分類。
- `DetailView.tsx` → `store.editCollection`／`store.editAttempt` → IndexedDB。沿用既有非同步交易及錯誤處理；只有保存成功才顯示已儲存，失敗時保持草稿。
- Prompt 文字變更後，舊的手動分類不會套到新文字位置。各次嘗試的分類獨立，與原始收藏互不影響；原始與嘗試 Prompt 都保持原文。

### 驗證

`pnpm test` 檢查中英文規則、英文詞界、未知／多類內容、括號權重、LoRA、不重複混淆的片段 ID、原文更改後不使用過期覆寫，以及收藏／嘗試分類獨立保存並從 IndexedDB 讀回。`pnpm typecheck` 與 `pnpm build` 檢查型別及建置。

瀏覽器已確認兩種 Prompt 都有原文／分類入口，差異介面消失，分類以緊湊詞句分區呈現。手動驗收可將一段未分類詞改到適合分類、儲存並重新整理，再確認分類仍在、複製仍取得完整原文；寫入失敗應保留分類草稿並允許重試。

## 第六次改善：等寬版面、分類卷軸與任選兩圖比較

- 詳情主頁預設「我的成果」。左側保留參考原圖與原始 Prompt，右側顯示成果及嘗試；桌面兩欄等寬。移除右側重複的「參考原圖」模式。
- `PromptReader.tsx`：分類內容固定在最高 480px／55vh 的獨立捲動區塊中，底部另放儲存分類與結果提示。展開原文也在區塊內捲動，不再無限拉長畫面。
- `ImageComparison.tsx`：並排比較專用兩欄，每欄是圖片 → 所屬 Prompt → 筆記，圖片框同高且 object-contain。桌面左右 50/50，手機整欄上下排列。比較頁不顯示底下原有的重複參考圖與嘗試縮圖列表。
- 「選擇比較圖片」以勾選方式選兩張：可比較參考／成果、不同嘗試或同一次嘗試的兩張圖；勾選順序決定左／右，可交換。已有兩張時先取消一張再更換。
- `comparisonImages.ts`：每個選项指向所屬嘗試，使用它的實際 Prompt 與分類保存路徑；參考圖則使用收藏原始 Prompt。選圖只是畫面狀態，不變更收藏圖片或 Prompt。

型別、建置及既有測試通過。新增選圖測試涵蓋對應版本、同次／不同次嘗試、選兩張上限、取消更換及空圖片。瀏覽器已確認兩張直式圖片等寬完整顯示，以及切换成 Gemini／PixAI 兩張成果時各自顯示正確 Prompt。
