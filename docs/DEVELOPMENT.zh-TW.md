## 目前版本狀態

Promptary 是以本機儲存為核心的 AI 生圖咒語收藏與嘗試紀錄工具，使用 React 19、TypeScript、Vite 8、Tailwind CSS v4 與 IndexedDB，網站透過 GitHub Pages 提供。

目前已完成收藏搜尋、標籤與狀態篩選、最愛、收藏與嘗試命名、評分、封面選擇、分類閱讀、手機雙圖比較、正體中文／英文切換、ZIP 備份，以及本機儲存資訊。另已加入範例收藏、首次使用介紹與「關於」視窗，以及自訂嘗試咒語的分類沿用。

收藏與圖片存在目前網站來源的瀏覽器中，沒有登入、雲端資料庫或跨裝置自動同步。Supabase 曾討論評估，但尚未實作；目前跨裝置搬移仍透過手動匯出與匯入 ZIP。

## 現行實作重點

### 首次使用與範例收藏

沒有現行圖庫或舊版資料時，畫面會先顯示隨網站附上的範例收藏，再將範例圖片排入佇列存進 IndexedDB。本機 Blob 尚未可用時，`StoredImage.tsx` 可以先顯示網站內的範例圖片。已有的圖庫會保留，包含使用者刻意清空後儲存的空圖庫，不會重新補入範例。

範例初始化與一般寫入共用佇列，提交前也會再次檢查是否已有圖庫；初始化失敗仍會釋放佇列，讓後續寫入繼續。資料庫開啟、首次讀取、範例圖片下載與解碼皆有逾時處理，避免停滯的操作讓初始載入畫面無限等待。這項替代顯示機制不代表無法使用的瀏覽器儲存空間會恢復可寫入。

圖庫會在尚未關閉過介紹時開啟精簡版「關於」，並以 `localStorage` 的 `promptary_intro_seen` 記住已讀狀態。「關於」按鈕則開啟完整版本，包含使用提醒、製作緣由與作者連結。視窗支援 Escape 關閉、鍵盤焦點限制在視窗內，以及關閉後將焦點移回按鈕；若瀏覽器無法保存偏好，下次可能再次顯示介紹。

### 圖片與儲存

收藏參考圖片與嘗試成果圖片共用處理流程，支援 JPEG、PNG、WebP，單檔上限 10 MiB、解碼上限 4,000 萬像素。

每次選圖最多 10 張，超過時在解碼前整批拒絕。每個表單最多同時處理 2 張，追加批次與重試共用佇列；關閉表單後不再啟動尚未開始的工作。

圖片保存為長邊最多 2048 像素的 canonical image，縮圖長邊最多 800 像素。優先輸出 WebP，必要時使用 JPEG／PNG 相容處理，並驗證實際輸出格式與解碼結果。

React 狀態保存圖片 ID 與中繼資料，圖片 Blob 和縮圖分開存入 IndexedDB。這些圖片經過處理，不保證與使用者原檔的位元組或尺寸相同。

資料更新經由 `store.ts` 排隊，等待 IndexedDB 交易成功後才更新畫面。儲存失敗時保留表單；資料版本檢查避免舊分頁直接覆蓋較新的收藏。

### 備份與本機資料

現行備份格式為 ZIP，包含 manifest、canonical 圖片及自訂平台清單，不包含可重新產生的縮圖。

匯入前檢查格式、版本、圖片資料、項目數量、大小與不安全路徑，先顯示預覽，確認後才寫入。收藏與圖片沿用交易式寫入，避免只匯入部分資料。

相同收藏 ID 依更新時間處理：備份較新就更新整筆收藏，本機較新或時間相同則保留。自訂平台採合併去重，不以備份清單直接覆蓋本機清單。

ZIP 驗證另會檢查中央目錄邊界與項目數，拒絕分卷壓縮檔與 ZIP64 定位紀錄，並確認未壓縮項目的大小一致。解壓時透過 `fflate` 篩選函式，在配置輸出緩衝區前，逐項比對檔名、壓縮大小、宣告解壓大小與壓縮方式是否符合預先檢查結果；項目遺漏、重複或資訊不一致都會使匯入失敗。

目前限制：

| 項目上限            |         |
| --------------- | ------- |
| ZIP 檔案          | 100 MiB |
| 宣告解壓總量          | 200 MiB |
| ZIP 項目數         | 10,001  |
| manifest        | 5 MiB   |
| 單項 canonical 圖片 | 20 MiB  |

舊版瀏覽器資料的遷移邏輯仍保留，但不代表目前匯入介面支援舊 JSON 備份。

Storage API 用於查詢用量、檢查及請求持續性儲存。瀏覽器不支援或拒絕時，功能仍可使用；持續性儲存不等於備份，也無法防止使用者主動清除網站資料。

### 咒語閱讀與表單

分類閱讀依本機中英文關鍵字規則產生，不使用 AI 語意分析。手動分類綁定當時的原文，避免原文修改後錯套舊分類；閱讀分類不改變複製內容。

新增嘗試的自訂咒語預設留空，可切換「無修改」使用原始咒語。資料以明確模式區分「沿用原始」與「自訂」，不只靠兩段文字是否相同判斷。

收藏與嘗試表單共用未儲存變更確認。這項保護涵蓋表單關閉操作，不是草稿自動保存；重新整理頁面仍可能失去未儲存內容。

建立自訂嘗試或修改咒語時，`inheritPromptClassification` 會以去除前後空白後的相同文字片段，沿用原始咒語的分類並保存快照。該次嘗試已有的手動分類優先保留，新片段則依本機關鍵字規則分類；咒語未變更時，保留原有分類。這是儲存當下的沿用，之後修改原始分類不會持續同步到自訂嘗試。

### 網站資源與部署

`index.html` 已加入 favicon、Apple 主畫面圖示、主題色與 web manifest。Manifest 使用相對的啟動網址與範圍，並設定獨立視窗顯示；這些資源提供瀏覽器與主畫面外觀，目前沒有 service worker 或離線應用程式快取。

GitHub Pages 工作流程透過 `lfs: true` 取得 Git LFS 資源，應保留此設定，避免發布的圖片實際上只是 LFS 指標文字。Vite 以 `PAGES_BASE_PATH` 處理子路徑部署，HTML 圖示連結使用 `%BASE_URL%`。

`public/_headers` 包含 Cloudflare 部署所用的 CSP 與快取等標頭；建置產物內有這份檔案，不代表其他代管平台也會套用。`.figma/make/site.json` 保留網站中繼資料，並透過 `robots.index: true` 允許索引。

HTML 已加入 Cloudflare Web Analytics 腳本，用於網站使用情況統計，樣式表也會載入 Google Fonts。本機保存收藏不代表網頁沒有對外連線；流量分析與瀏覽器圖庫分開，不提供雲端備份或同步。

基本檢查：

```
pnpm typecheck

```

應針對正在修改的版本執行上述檢查，早期版本通過不代表後續版本也已驗證。測試涵蓋圖片處理、批次上限與併行控制、儲存與遷移、ZIP 備份與異常壓縮檔拒絕、收藏流程、自訂平台、分類沿用與比較選圖、表單關閉規則，以及範例資料載入與替代處理。部分介面檢查屬程式結構檢查，不能取代瀏覽器實際操作。

涉及圖片與手機操作時，仍應手動確認選圖、完成儲存、重新整理後讀回、第二批追加、關閉表單及備份還原。測試通過不代表已量測所有裝置的記憶體使用量或處理時間。

另需確認首次介紹關閉後不再自動出現、「關於」能重新開啟、新圖庫的範例載入，以及既有或刻意清空的圖庫不被補入範例。部署變更除了建置成功，也應核對發布後的圖片實際位元組與資源路徑。

後續維持小範圍修改；如要加入登入或跨裝置自動同步，再另行規劃資料同步與衝突處理。目前不將這些討論視為已完成功能。
