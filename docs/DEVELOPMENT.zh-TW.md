## 目前版本狀態

Promptary 是以本機儲存為核心的 AI 生圖咒語收藏與嘗試紀錄工具，使用 React 19、TypeScript、Vite 8、Tailwind CSS v4 與 IndexedDB，網站透過 GitHub Pages 提供。

目前已完成收藏搜尋、標籤與狀態篩選、最愛、收藏與嘗試命名、評分、封面選擇、分類閱讀、手機雙圖比較、繁體中文／英文切換、ZIP 備份，以及本機儲存資訊。

收藏與圖片存在目前網站來源的瀏覽器中，沒有登入、雲端資料庫或跨裝置自動同步。Supabase 曾討論評估，但尚未實作；目前跨裝置搬移仍透過手動匯出與匯入 ZIP。

## 現行實作重點

### 圖片與儲存

收藏參考圖片與嘗試成果圖片共用處理流程，支援 JPEG、PNG、WebP，單檔上限 10 MiB、解碼上限 4,000 萬像素。

每次選圖最多 10 張，超過時在解碼前整批拒絕。每個表單最多同時處理 2 張，追加批次與重試共用佇列；關閉表單後不再啟動尚未開始的工作。

圖片保存為長邊最多 2048 像素的 canonical image，縮圖長邊最多 800 像素。優先輸出 WebP，必要時使用 JPEG／PNG 相容處理，並驗證實際輸出格式與解碼結果。

React 狀態保存圖片 ID 與中繼資料，圖片 Blob 和縮圖分開存入 IndexedDB。這些圖片經過處理，不保證與使用者原檔的位元組或尺寸相同。

資料更新經由 `store.ts` 排隊，等待 IndexedDB 交易成功後才更新畫面。儲存失敗時保留表單；資料版本檢查避免舊分頁直接覆蓋較新的收藏。

### 備份與本機資料

現行備份格式為 ZIP，包含 manifest、canonical 圖片及自訂平台清單，不包含可重新產生的縮圖。

匯入前檢查格式、版本、圖片資料、項目數量、大小與不安全路徑，先顯示預覽，確認後才寫入。收藏與圖片沿用交易式寫入，避免只匯入部分資料。

相同收藏 ID 依更新時間處理：備份較新就更新整筆收藏，本機較新或時間相同則保留。自訂平台採合併去重，不以備份清單直接覆蓋本機清單。

目前限制：

| 項目上限            |         |
| --------------- | ------- |
| ZIP 檔案          | 100 MiB |
| 宣告解壓總量          | 200 MiB |
| ZIP 項目數         | 10,001  |
| manifest        | 5 MiB   |
| 單項 canonical 圖片 | 20 MiB  |

舊版瀏覽器資料的遷移邏輯仍保留，但不代表目前匯入介面支援舊 JSON 備份。

Storage API 用於查詢用量、檢查及請求持續性儲存。瀏覽器不支援或拒絕時，功能仍可使用；持續性儲存不等於備份，也無法防止使用者主動清除網站資料。

### 咒語閱讀與表單

分類閱讀依本機中英文關鍵字規則產生，不使用 AI 語意分析。手動分類綁定當時的原文，避免原文修改後錯套舊分類；閱讀分類不改變複製內容。

新增嘗試的自訂咒語預設留空，可切換「無修改」使用原始咒語。資料以明確模式區分「沿用原始」與「自訂」，不只靠兩段文字是否相同判斷。

收藏與嘗試表單共用未儲存變更確認。這項保護涵蓋表單關閉操作，不是草稿自動保存；重新整理頁面仍可能失去未儲存內容。
